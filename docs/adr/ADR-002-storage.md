# ADR-002. Хранилище: PostgreSQL

**Статус:** принято · **Связанные требования:** ТЗ СЧ приложение Б.2, NFR-09, NFR-10, NFR-18, NFR-25, NFR-28, NFR-31, FR-51

Система учёта — PostgreSQL 16 (выбор ТЗ СЧ, матрица Б.2). Схема задаётся SQL-миграциями `server/migrations`,
которые применяются при старте и командой `node server/dist/cli.js migrate` под рекомендательной блокировкой.

Узел API держит рабочий набор данных в памяти и записывает изменения в PostgreSQL одной транзакцией;
изменяющий запрос API получает ответ только после фиксации (хук `onSend` в `app.ts`), при сбое БД — 503
с Retry-After. Версии ответов хранятся в отдельной таблице `answer_versions` (только добавление). Журнал
событий защищён триггерами от UPDATE, DELETE и TRUNCATE. Аналитические витрины — схема `analytics` без ПДн,
доступ роли `ege_analyst` только на чтение.

Развёртывание — `docker-compose.yml`: PostgreSQL, приложение, Nginx с TLS; секреты — файлы Docker secrets.

Ограничения: активен один узел API (сеансы, ключи идемпотентности, блокировки входа и канал событий — в памяти
процесса), поэтому NFR-28 (узлы без состояния) и синхронная репликация на ≥ 2 узла (RPO = 0, NFR-09)
требуют следующего шага: перенос этих данных в PostgreSQL, LISTEN/NOTIFY для событий, реплика
`synchronous_standby_names`.
